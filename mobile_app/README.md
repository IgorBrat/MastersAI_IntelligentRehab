# mobile_app — folder map

Flutter Android client. Kotlin captures camera frames and runs pose estimation;
everything else, including scoring, the model and the coach, runs in Dart on the
phone. Full detail is in `README.md`.

## Top level

| Folder | Contents |
|---|---|
| `lib/` | All Dart code |
| `assets/` | Bundled scoring configuration: calibrated thresholds and model weights |
| `android/` | Android project, including the Kotlin native layer and the MediaPipe pose models |
| `test/` | Dart tests, including the Python→Dart parity suite |

## Inside `lib/`

| File / folder | Role |
|---|---|
| `main.dart` | Entry point and app shell |
| `config.dart` | Constants — fallback frame rate, window size |
| `pose/` | `pose_stream.dart` — receives landmark frames from Kotlin over the event channel |
| `analysis/` | Live, per-frame analysis: joint angles and girdle height (`live_angles`), repetition detection (`rep_detector`), phase cues (`cues`), speech (`spoken_cues`) |
| `scoring/` | On-device scoring pipeline, a port of the Python `rehab_ml` (see below) |
| `api/` | Data types shared by the screens; HTTP client used only for the optional laptop video mode |
| `clinical/` | Ukrainian names of errors and coach decisions |
| `state/` | App-wide state: profile, session history, the scoring engine |
| `storage/` | Local persistence — profile, sessions and recordings as JSON |
| `screens/` | One file per page |
| `widgets/` | Reusable UI, currently the skeleton overlay |

### `scoring/`

| File | Role |
|---|---|
| `signal.dart` | Numerical routines matching scipy/numpy: Butterworth, `filtfilt`, Savitzky–Golay, `find_peaks`, FFT |
| `pose.dart` | MediaPipe landmarks → canonical 18-joint skeleton, preprocessing |
| `angles.dart` | The 14 clinical angle channels |
| `kinematics.dart` | Tempo, range of motion, SPARC, LDLJ |
| `exercises.dart`, `taxonomy.dart` | Exercise protocol, error types, threshold file |
| `rules.dart` | Segmentation, graded criteria, quality index (EQI), framing check |
| `model.dart` | Model features and the hybrid network's forward pass |
| `adaptation.dart` | Load decisions and coach text (Gemini or template) |
| `rehab_engine.dart` | Entry point used by the screens; runs scoring on a background isolate |

### Screens

| File | Page |
|---|---|
| `home_shell.dart` | Bottom navigation container |
| `exercise_screen.dart` | Pick an exercise and start a set |
| `record_screen.dart` | Live camera, skeleton overlay, real-time cues |
| `summary_screen.dart` | Results for a finished set |
| `history_screen.dart` | Past sessions, stored locally |
| `profile_screen.dart` | Name, age, affected arm, scoring status |
| `coach_screen.dart` | Adaptive progression advice |
| `video_screen.dart` | Scoring a clip stored on a laptop, for testing |

## Tests

| File | Checks |
|---|---|
| `scoring_parity_test.dart` | Every scoring stage against Python output in `test/golden/` |
| `rehab_engine_test.dart` | Bundled assets, background isolate, coach without network |
| `live_angles_test.dart` | Live angles against Python reference values |
| `cues_test.dart`, `rep_detector_test.dart`, `spoken_cues_test.dart`, `storage_test.dart` | Live cues, repetition counting, speech, persistence |

`test/golden/` is generated by `ml/scripts/export_dart.py golden`; regenerate it
after any change to `ml/rehab_ml`.

## Native layer

`android/app/src/main/kotlin/ua/lpnu/intelligent_rehab/` holds two files:

| File | Role |
|---|---|
| `MainActivity.kt` | Registers the event and method channels |
| `PoseStreamHandler.kt` | CameraX capture plus MediaPipe pose estimation |

Kotlin does capture and pose estimation only. It emits raw landmarks with their
capture timestamps and knows nothing about repetitions, errors or scoring.

## Running

```bash
flutter run --dart-define=GEMINI_API_KEY=...   # the key is optional
```
